# lume-ambilight

**Самодельный Ambilight для Mac по BLE, без переделки железа.**
Панель Lume Cube Panel Pro 2.0 за монитором повторяет цвет экрана в реальном времени.
Официальное приложение не нужно (достаточно один раз «усыновить» в нём панель),
облака нет, всё локально.

Протокол полностью восстановлен реверсом официального приложения и проверен на живой
панели. [English README →](README.md)

## Что умеет

- **Ambilight**: панель следит за цветом экрана — захват ~18 кадров/с, ~19 обновлений
  по BLE в секунду, экспоненциальное сглаживание (без мерцания).
- **Полный CLI**: питание, RGB, белый с температурой (CCT), встроенные эффекты, чтение
  статуса с проверкой MIC.
- **Софтовые эффекты**: свеча, гроза, радуга, пульс, полицейский строб, северное сияние.
- **Автоподхват кредов**: имя меша, пароль, MAC и UUID панели читаются из контейнера
  официального приложения — ничего не хардкодится.

## Как устроен Ambilight

Цвет берётся из **центра кадра** (область 68%×64%) со взвешиванием по насыщенности
(`sat²` — сочные пиксели решают, серость не тянет), почти чёрное пропускается.
Выбрано A/B-тестом против краёв кадра: панель одна, маленькая, по центру — края ей не
подходят. Демон сглаживает переходы (lerp, α=0.18), бустит насыщенность ×1.8.

Флаги: `--brightness 0.85`, `--saturation 1.8`, `--rate 20`, `--smooth 0.18`.

## Быстрый старт

Нужны: macOS с Bluetooth, Python 3.10+, Xcode CLT и сама панель.

```sh
git clone https://github.com/denis0wn/lume-ambilight
cd lume-ambilight
python3 -m venv venv && venv/bin/pip install -r requirements.txt
swiftc -O ambicap.swift -o ambicap
```

Один раз спарьте панель с официальным приложением Lume Cube (дальше оно не нужно —
креды читаются из его контейнера автоматически):

```sh
venv/bin/python lume.py status        # должно напечатать состояние панели
venv/bin/python ambilight.py          # панель следует за экраном; Ctrl+C — стоп
```

Без официального приложения на этой машине — переменные окружения:
`LUME_ADDR`, `LUME_MAC`, `LUME_MESH_NAME`, `LUME_PASSWORD`
(или `LUME_PLIST` на plist, скопированный с другого Mac).

> На macOS CoreBluetooth прячет настоящие MAC и даёт каждому Mac свой UUID периферии —
> поэтому оба значения берутся из записи официального приложения. На Linux у bleak
> сразу настоящий MAC — задайте `LUME_ADDR`.

## Команды

```sh
lume.py on | off                        # питание
lume.py status                          # статус (расшифровка с MIC)
lume.py color R G B                     # 0..255
lume.py white T B                       # T: 0=тёплый..255=холодный
lume.py effect fire                     # siren|strobe|fire|cycle|police
effects.py aurora                       # candle|lightning|rainbow|heartbeat|police2|aurora
scan.py                                 # найти панель (анонс «Telink tLight»)
explore.py                              # дамп GATT
```

Панель держит одно BLE-подключение: пока подключено официальное приложение — наш код
не подключится (и наоборот).

## Протокол

Панель говорит на **Telink legacy mesh** (не SIG Mesh). Сервис
`00010203-0405-0607-0809-0a0b0c0d1910`, характеристики: `1914` — паринг,
`1912` — команды, `1911` — нотификации, `1913` — OTA.

**Паринг** (официальный поток Telink SDK): `0x0C + randm8 + reverse(enc[8:16])`,
где `enc = AES-128-ECB(key=reverse(randm+0⁸), data=reverse(name⊕password))`.
Ответ `0x0D + rands + proof`; session key = `reverse(AES(name⊕pass, randm+rands))`.
`0x0E` = неверные креды. После паринга записать `01` в `1911` — включает пуш статусов.

**Команды** (20 байт): `seq3 | MIC2 | enc15(dest2 LE + opcode + vendor 1102 + params)`,
AES с разворотом входа И выхода (конвенция dimond/AwoX). Nonce: `mac_rev[0:4]+01+seq3`.
Писать **на broadcast 0xFFFF** — на unicast панель не отвечает.

**Опкоды (проверены вживую):**

| Команда | Опкод | Payload |
|---|---|---|
| Вкл/выкл | `0xD0` | `[01]` / `[00]` |
| RGB | `0xE2` | `[04, R, G, B]` |
| Белый CCT | `0xE2` | `[06, temp, bright]` |
| FX-эффект | `0xE2` | `[0A, N, speed, bright]` (0 сирена, 1 строб, 2 огонь, 3 цикл, 5 полиция) |
| Статус | `0xDA` | ответ `0xDB`, параметры с байта 10 |

Классические AwoX-опкоды (`0xF0/0xF1/0xF2`, `0x33`, `0xC8`, `0xD2`, `0xEE`) на этой
прошивке (V0.C) молча игнорируются. Эффекты найдены реверсом приложения
(objc-танки `onFireTouched` и др. → структуры `[0A, N]` в `__data`).

## OTA — осторожно

`ota.py` реализует legacy-поток прошивки (prepare → start → пакеты с CRC16-Modbus →
финишер → end). Проверено на живой панели: образ принимается целиком, но панель
**валидирует product id** в заголовке (магия `0x8026`, смещение `0x1C`) — чужой образ
отклоняется. Неудачный `PREPARE` может оставить панель в OTA-режиме до переадоптации
официальным приложением (при этом имя меша ротируется). В `1913` без нужды не писать.

## Ограничения

- Панель однозональная (один RGB+W канал) — это подсветка, не градиентная стена.
- Одно BLE-подключение одновременно.
- Захват экрана пока только под macOS (`CGWindowListCreateImage`); сам BLE-слой
  кроссплатформенный (bleak).
- Не слать `0xE0` (смена адреса) и `0xE3` (сброс) без нужды.
